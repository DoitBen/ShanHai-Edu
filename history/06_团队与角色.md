# 团队与角色

产品由谁参与了哪些决策、谁负责什么。

---

## 决策参与方

### 产品负责人（用户本人）
- **角色**：教研团队成员 + 产品 owner
- **背景**：
  - 真正用过原工作流踩过坑（识别屎山的能力来自实战）
  - 清楚教研团队真实需求（每节课的工作流就是他们日常）
  - 清楚资源结构（"我们做的就是老师"）
  - 对合规问题有工程化思维（"约定死角色描述就不会侵权"）
- **核心判断风格**：
  - 拒绝过度设计
  - MVP 优先
  - 识别成本结构
  - 不容忍屎山
  - 现实主义资源观

### AI 助手（Claude）
- **角色**：陪伴讨论、提炼判断、写产品文档和规范
- **能力边界**：
  - 不能判定教学法对错
  - 不能验证商业模型
  - 能识别"屎山结构"和"半自动化产品需要的输入"
  - 能把对话沉淀成可执行的工程文件

### 待定的关键角色

#### 教学法负责人
- **职责**：维护 workflow.yaml / rules / prompts 中教学法相关部分
- **背景要求**：
  - 懂小学数学新课标 2022
  - 懂公开课评议标准
  - 能看懂 yaml 文件改字段
- **当前状态**：未指派
- **决定 deadline**：v1 上线前必须有

#### 全栈开发主导
- **职责**：
  - 主导技术架构落地
  - Python 后端为主
  - 状态引擎 / 规则执行器 / LLM 调用层
- **当前状态**：未招聘

#### 前端开发
- **职责**：
  - Next.js + React 工作流可视化
  - 字段化表单（按 JSON Schema 自动渲染）
  - 异步任务进度可视化
- **当前状态**：未招聘

#### AI 接入工程师（0.5 人）
- **职责**：
  - 每节点 × 每 provider 的 prompt 调优
  - 跨 provider 输出一致性测试
  - 视频 / 图片模型对接
- **当前状态**：未招聘

#### DevOps（0.2 人）
- **职责**：
  - Docker Compose 部署
  - 监控告警
  - 备份策略
- **当前状态**：未招聘

## 决策权分布

### 产品红线决策
- **谁定**：产品负责人 + 教学法负责人 + 法务（合规相关时）
- **不可被开发推翻**
- **例**：中文男声硬约束、禁真人未成年、数学进可编辑层

### 流程结构决策
- **谁定**：产品负责人
- **可与教学法负责人协商**
- **例**：9 步流程顺序、节点字段范围、状态机转换规则

### 技术选型决策
- **谁定**：全栈主导 + 产品负责人
- **可挑战技术路线规划中的选型**
- **例**：前端框架、数据库、任务队列

### prompt 调优决策
- **谁定**：AI 接入工程师 + 教学法负责人
- **不直接改 prompt 的人不参与**
- **例**：教案 prompt 的语言风格档位

### 飞轮策略决策
- **谁定**：产品负责人
- **依赖数据**
- **例**：注入几个 approved 样例、何时启 fine-tune

## 沟通约定

### workflow.yaml / schemas / rules 的修改
- 必须走 Pull Request
- 至少 1 个 reviewer（产品 or 教学法负责人）
- CI 必须通过（yaml lint + schema 校验）

### prompts/ 的修改
- AI 接入 + 教学法负责人共同 review
- 跑回归测试（每节点至少 1 个用例）

### 红线规则的修改
- 必须产品负责人 + 教学法负责人 + 法务（如涉及）三方同意
- 不允许"快速 hotfix"

### v1.x 范围扩张
- 产品负责人决定（依据飞轮数据 + 用户反馈）
- 不允许开发主动加 v1 不在范围的功能

## 招聘建议

### 全栈主导（最关键）
- 优先级：S
- 必须能力：
  - Python 后端深厚（FastAPI / SQLAlchemy）
  - 懂状态机 / 规则引擎
  - 懂 LLM API（多 provider 适配经验加分）
  - 能读 ppt-master 现有代码
- 加分能力：
  - 懂教育产品
  - 懂 Next.js（能 review 前端代码）

### 前端
- 优先级：A
- 必须能力：
  - Next.js + React + TypeScript
  - 表单驱动开发经验（react-hook-form / formik）
  - 懂 JSON Schema
- 加分能力：
  - 懂 SSE / WebSocket
  - 设计感（教研用户对 UI 有要求）

### AI 接入
- 优先级：A
- 必须能力：
  - 跑过 DeepSeek / Claude / GPT 任一家的 API
  - 懂 prompt engineering
  - 中文母语
- 加分能力：
  - 懂多模态 API（图片 / 视频）
  - 懂教育领域

### 教学法负责人
- 优先级：S（v1 上线前必须有）
- 必须能力：
  - 教研员或一线小学数学老师背景
  - 懂新课标 2022
  - 愿意学 yaml 改字段
- 加分能力：
  - 写过教研论文
  - 公开课评议经验

## 用户的判断风格档案（用于团队 align）

详见 `02_关键拐点.md` 最后"用户的产品判断风格"节。

8 个特征摘要：
1. 拒绝过度设计
2. 资源现实主义
3. MVP 优先
4. 识别成本结构
5. 不容忍屎山
6. 要求可消费
7. 接受不确定
8. 绝对主导权信念

**这些特征本身是产品的隐性资产。开发团队理解后能保持判断一致性。**

## 责任 RACI 矩阵（v1 阶段）

| 决策类型 | R | A | C | I |
|---|---|---|---|---|
| 产品红线 | 产品 | 产品 | 教学法 / 法务 | 全员 |
| 流程结构 | 产品 | 产品 | 教学法 / 全栈 | 全员 |
| 技术选型 | 全栈 | 全栈 + 产品 | 前端 / AI 接入 | 全员 |
| Schema 字段 | 全栈 | 产品 | 教学法 | 全员 |
| Prompt 调优 | AI 接入 | AI 接入 | 教学法 | 产品 |
| 飞轮策略 | 产品 | 产品 | 全栈 | 全员 |
| 部署运维 | DevOps | 全栈 | 产品 | 全员 |
| 教程内容 | 教学法 | 产品 | 全栈 / 前端 | 全员 |

R=Responsible（执行）/ A=Accountable（决策）/ C=Consulted（咨询）/ I=Informed（知会）

## 团队未到位前的判断

当前阶段产品负责人 + AI 助手二人作业。
团队招聘和 v1 上线是并行的，不能等团队齐了才动手。

判断顺序：
1. **先招全栈主导和教学法负责人**（最关键）
2. **同时启动 v1 前 1 月骨架开发**（全栈主导可以兼任前端的早期版本）
3. **第 2 月再补前端 + AI 接入**
4. **DevOps 上线前补**

这样能压缩到 3 人 × 3 月。
