# 前端设计路线 v3

版本：2026-06-20 v3
当前实现：`apps\web\src\app\globals.css`
原型参考：`prototype-workbench-v2.html`

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| 教研工作台 | 不是营销页，也不是纯运维后台；核心用户是教研员和教师，需要长时间阅读、确认、编辑和推进公开课生产流程。 |
| 暖纸白主基调 | 默认使用暖纸白、深青灰、古铜金，降低长文档审核压力，保留教育内容生产的温润感和可信度。 |
| 线性推进 | 页面信息服务 9 步生产链路，用户应始终知道当前位置、下一步、是否可继续。 |
| 状态可见 | 每个项目、节点、队列和审核动作都要有清晰状态：完成、进行中、待确认、阻塞、失败。 |
| 克制质感 | 用字体层级、留白、边框和轻阴影建立层次，不依赖大面积渐变、强装饰或复杂插画。 |

## 2. 视觉规范

### 色板

| 类别 | Token | 值 | 用途 |
|------|-------|----|------|
| 背景层 | `--background` | `#f6f5f1` | 页面底色，暖纸白 |
|        | `--card` | `#ffffff` | 卡片、表单、弹层内容 |
|        | `--muted` | `#efece5` | 弱背景、筛选栏、辅助区域 |
| 主色 | `--primary` / `--brand` | `#2d4356` | 主按钮、当前态、焦点、品牌字色 |
| 强调 | `--bronze` | `#9c7c4e` | 编号、当前状态点、品牌点缀 |
| 文字 | `--foreground` | `#23272e` | 主文字 |
|      | `--muted-foreground` | `#5c636e` | 次级文字、说明、占位 |
| 边框 | `--border` | `#ddd9d0` | 卡片、输入、分隔线 |
| 状态 | `--success` | `#4f6b59` | 完成态 |
|      | `--warning` | `#9a7340` | 运行中、警告 |
|      | `--info` | `#45627a` | 信息态 |
|      | `--destructive` | `#9a4747` | 错误、危险操作 |

规则：

- 状态色优先用于 Badge、文字和小图标，不做大面积背景。
- 主 CTA 使用 `primary`，次级动作使用 outline/ghost。
- `bronze` 只做序号、当前节点、品牌提示，不抢主操作。

### 字体

- 字体族：系统无衬线栈，中文优先：`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC` 等。
- 层级工具类：
  - `.t-title`：页面标题
  - `.t-module`：模块标题
  - `.t-body`：正文和控件文字
  - `.t-caption`：辅助说明
  - `.t-overline`：分区标签和编号
- 不再使用负字距或视口缩放字号；长文本优先换行、截断或内部滚动。

### 圆角与阴影

- 全局圆角基准：`--radius: 0.625rem`。
- 卡片：约 10px，保持工作台质感。
- 按钮：随 shadcn Button 组件体系。
- 阴影只用 `shadow-soft` 和 `shadow-lift`，避免厚重浮层。

## 3. 布局结构

```text
┌─────────────────────────────────────────────────────┐
│  侧边栏 256px                                      │
│  ┌─ Logo / ProMax 工作台 ─────────────────────┐     │
│  ├─ 导航：首页 / 新建项目 / 当前项目 / 配置... │     │
│  ├─ 系统轻状态：调度器 / 队列 / 存储           │     │
│  └─ 使用指引                                   │     │
├─────────────────────────────────────────────────────┤
│  顶栏 64px：面包屑 / 搜索 / 主题 / 通知 / 用户 │     │
├─────────────────────────────────────────────────────┤
│  内容区：max-width 1440，桌面 32px 内边距       │     │
│  ├─ 页面标题与主操作                           │     │
│  ├─ 当前最重要工作区                           │     │
│  └─ 列表 / 表格 / 表单 / 日志                   │     │
└─────────────────────────────────────────────────────┘
```

移动端：

- 侧栏进入左侧 Sheet。
- 顶栏保留菜单、LogoMark、搜索、主题、通知、用户。
- 表格、节点轨、Tabs 可横向滚动，但主 CTA 和关闭/保存按钮必须可见。

## 4. 核心页面规范

### 首页 / Dashboard

- 主任务：继续最近项目或新建项目。
- “继续工作”是首页视觉主角。
- 项目概览支持搜索、筛选和排序，但不能压过继续工作。
- 系统轻状态只显示必要运行信息，不做监控大盘化。

### 新建项目

新建项目必须固化第 0 步核心上下文：

- 基本信息：课题、学科、年级、教材版本、册次、课型。
- 教材输入：上传或粘贴内容，解析后确认。
- 角色字典：非写实角色、多视角描述、服装发型锁定、禁真人约束。
- 视觉契约：主配色、风格关键词、字体偏好。
- 合规红线：中文男声、禁英文配音、禁真实未成年人、多分镜终版、候选不冒充终版。
- 交付配置：视频方向、PPT 风格、输出路径、安全模式。

### 项目工作区

- 主任务：线性推进当前节点。
- 每个节点详情底部只允许一个最高权重主 CTA。
- 辅助动作包括保存、重新生成、退回修改，视觉权重必须低于主 CTA。
- 节点状态必须让用户明确知道：能否生成、是否运行中、是否待确认、是否可进入下一步。

### 配置 / 日志 / 脚本

- 明确标注演示数据、占位数据或真实后端数据。
- 密钥只显示状态，不显示明文。
- 错误和日志信息使用用户能理解的语言，避免直接暴露 stack 或 token。

## 5. 组件约定

- 基础组件使用 shadcn/ui + Radix UI，不自造等价组件。
- 图标使用 `lucide-react`。
- 表单字段必须有 label，placeholder 只作示例，不替代 label。
- 按钮分层：
  - 主 CTA：当前状态下唯一最高权重动作。
  - 次按钮：保存、重新生成、查看流程等辅助动作。
  - Ghost/文本按钮：返回、重置、低频入口。
  - 危险按钮：退回、删除、停用，必须有明确文案。
- 弹窗和表格在窄屏必须保证关闭、确认、保存可达。

---

## 6. 动效与性能

- 页面切换使用轻量过渡，不为装饰增加重动画。
- 首屏入口不得静态引入所有大页面。
- 大 screen、命令面板、重表格和媒体预览优先动态加载。
- loading 占位必须轻，不应反向引入 Radix、lucide、skeleton 等重依赖。
- 尊重 `prefers-reduced-motion`，后续新增动效需提供降级。

---

## 7. 验收口径

- 首屏打开不应编译整个工作台模块图。
- 1440 / 1280 / 1024 / 768 / 390 宽度下无阻断主任务的横向溢出。
- 用户 5 秒内能判断当前页面用途、当前状态和下一步。
- 每个节点状态只有一个最高权重主操作。
- 新建项目必须包含角色字典、视觉契约和合规红线。
- 正式环境不展示演示账号或硬编码密码。
