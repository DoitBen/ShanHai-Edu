# 教材导入与工作区用户态重构需求说明

## 1. 背景与目标

本轮重构解决两个连续反馈暴露出的核心问题：

1. 新建项目阶段的教材库、教材字段、知识点、教材证据包和教案参考混排，用户难以理解。
2. 创建项目后的工作区页面暴露了 `StateEngine`、`schema`、manifest、JSON、日志、依赖门禁等工程信息，普通教师不知道当前该做什么。

本轮目标是把普通教师看到的页面从“工作流节点调试台”改成“公开课备课工作台”：

- 用户只看当前步骤、要做什么、结果是什么、下一步按钮。
- 已完成步骤可回看，未解锁步骤不可进入。
- 开发诊断保留，但默认隐藏在折叠区。
- 教材内容、教案、视频方案三类产物命名清楚，不能混用。

核心服务对象仍是 P01 李雪老师：小学数学教师，不懂 API、schema、prompt、状态机、命令行，只接受“填表 -> 看结果 -> 改一改 -> 确认下一步”的操作方式。

## 2. 用户态词汇统一

普通用户页面必须使用下列词汇：

| 用户态名称 | 含义 | 禁止替代词 |
|---|---|---|
| 教材内容 | MinerU 从教材页段解析出的 Markdown 和图文结构化内容 | 教案、JSON、node content |
| 教案 | 基于教材内容生成的公开课教案 Markdown | 教材解析结果、JSON |
| 教材依据 | 当前知识点对应的页段 PDF、截图、Markdown 和页码来源 | 证据文件、artifact |
| 当前步骤 | 用户正在处理的备课环节 | 当前节点、manifest node |
| 生成草稿 | 让系统生成当前步骤内容 | run、execute |
| 确认并进入下一步 | 用户审核当前步骤后推进 | approve、state transition |
| 回看 | 查看已完成步骤内容 | 切节点、查看 version |
| 修改本步骤 | 退回并编辑已完成步骤 | reject、redo、cascade |
| 开发诊断 | 工程师排障信息 | StateEngine、schema、R010、日志 |

普通用户主界面不得出现：

- `StateEngine`
- `schema`
- `manifest`
- `R010`
- `dependency_gate`
- `JSON`
- `node_id`
- `输出路径`
- `安全模式`
- `API`
- `provider`

这些信息只允许出现在“开发诊断”折叠区，默认关闭。

## 3. 新建项目流程要求

### 3.1 第一步：选择教材来源

页面目标：让用户先确定教材，而不是先填一堆项目配置。

必须提供两个入口：

1. 从教材库选择。
2. 上传新教材解析。

教材库选择必须是下拉框，展示格式：

```text
人教版 / 小学数学 / 一年级 / 上册
```

不得只显示“教材库默认教材”按钮。

### 3.2 第二步：选择目录章节或课时知识点

页面目标：先选择教材内容范围，再回填项目字段。

页面顺序：

1. 教材下拉框。
2. 目录章节/知识点下拉框。
3. 页码范围提示。
4. 教材字段回填区。
5. 教材证据包摘要。

知识点数据只允许来自后端，不允许前端写死。

教材字段必须集中排版：

- 学科
- 年级
- 教材版本
- 册次
- 教材标题
- 项目名称
- 课型
- 目标受众

目标受众默认值应来自教材年级，例如“一年级学生”。

### 3.3 教材证据包展示

主页面只显示摘要：

- 教材页码
- PDF 页码
- 解析状态
- 人工确认状态

操作按钮：

- 查看教材页段
- 查看教材内容
- 查看核心知识点
- 重新解析当前知识点
- 确认教材内容

核心知识点不得常驻铺开，必须通过按钮打开抽屉或弹窗结构化展示。

### 3.4 教案参考

教案库是参考层，不是主输入。

页面只能展示教案参考摘要卡：

- 标题
- 来源教材
- 知识点
- 更新时间
- 是否与当前教材匹配

正文通过“查看教案”右侧抽屉打开。抽屉内允许：

- 查看教案 Markdown。
- 选为参考。
- 复制内容。

复制成功或失败必须有 toast 反馈。

### 3.5 视频与 PPT 配置

关键词必须改成标签多选：

- 支持从建议标签中选择。
- 支持用户自定义标签。
- 用户自定义标签要在当前项目中保留。

预计时长必须支持：

- 下拉选择。
- 自定义输入。

PPT 结构必须使用固定模板下拉，例如：

- 导入-探究-归纳-练习-小结
- 情境-问题-操作-表达-应用
- 复习-新知-例题-练习-总结

普通用户不得看到：

- 输出路径
- 安全模式

配置摘要允许保留，但必须按分组呈现：

- 教材
- 教案
- 视频
- PPT

## 4. 工作区用户态流程要求

### 4.1 顶部流程导航

工作区顶部不再直接展示后端 manifest 节点。普通用户看到 7 个用户态步骤：

1. 项目信息
2. 教材内容
3. 教案生成
4. 导入视频方案
5. PPT 草稿
6. 视频生成
7. 最终交付

每个步骤有三种用户态状态：

| 状态 | 用户行为 |
|---|---|
| 已完成 | 可以点击回看 |
| 当前步骤 | 可以查看、编辑、生成、确认 |
| 未解锁 | 灰色锁定，不允许进入 |

点击未解锁步骤时，不进入详情页，只提示：

```text
请先完成上一阶段。
```

如果可以明确上一阶段名称，则提示：

```text
请先完成【教材内容】后，再进入【教案生成】。
```

### 4.2 当前步骤任务卡

主区域必须是任务卡，而不是 5 个技术 Tab。

任务卡包含：

- 这一步要完成什么。
- 你现在需要做什么。
- 当前系统结果。
- 可编辑区域。
- 教材依据或生成依据。
- 唯一主按钮。

主按钮文案根据状态变化：

| 状态 | 主按钮 |
|---|---|
| 没有草稿 | 生成草稿 |
| 已生成待确认 | 确认并进入下一步 |
| 需要修改 | 保存修改 |
| 正在生成 | 生成中 |
| 已完成 | 查看下一步 |

### 4.3 已完成步骤回看

已完成步骤必须可回看。至少支持回看：

- 项目配置。
- 教材来源。
- 已选知识点。
- 教材内容 Markdown。
- 教案 Markdown。
- 导入视频方案。
- PPT 结构和风格。

回看默认只读。

如果用户点击“修改本步骤”，需要先提示影响范围：

```text
修改教材内容后，教案、导入视频方案、PPT 草稿可能需要重新确认。
```

### 4.4 未解锁步骤规则

未解锁步骤不得展示空内容、后端错误、依赖失败或技术日志。

用户只能看到：

- 为什么还不能进入。
- 应该先完成哪一步。

示例：

```text
还不能生成分镜脚本。
请先确认【导入视频素材】。
```

不得显示：

```text
UPSTREAM_NOT_APPROVED
R010
dependency_gate_blocked
```

### 4.5 教案展示规则

教案必须以 Markdown 编辑/预览方式呈现。

不得让普通用户直接编辑 JSON。

教案页面至少有：

- Markdown 编辑
- Markdown 预览
- 保存修改
- 确认并进入下一步

### 4.6 开发诊断折叠区

保留开发诊断，但默认关闭。

标题统一：

```text
开发诊断
```

内部可以展示：

- StateEngine 状态
- schema
- 原始 JSON
- 日志
- 依赖信息
- provider 错误

普通用户默认不需要看到。

## 5. 页面验收红线

以下任一出现即不通过：

1. 普通用户主界面出现 `StateEngine`、`schema`、`JSON`、`R010`、manifest、输出路径、安全模式。
2. 未解锁步骤可以点击进入详情。
3. 当前步骤没有明确主按钮。
4. 已完成步骤不能回看。
5. 教案正文以 JSON 展示。
6. 教材内容和教案命名混用。
7. 上游未确认错误只显示技术原因，不告诉用户下一步做什么。

## 6. 角色协作口径

- 后端负责提供用户态步骤契约、教材目录/页码/资产包真实数据。
- 前端负责按用户态流程展示，不直接暴露后端节点结构。
- 测试按本文件验收用户路径和截图，不只看接口返回。
- 架构师按本文件、任务台账、测试报告和关键 diff 做最终复核。
