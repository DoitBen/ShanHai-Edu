# v1 产品决策记录

版本：2026-06-18 第二版（重写）
状态：待评审
来源：2026-06-18 两轮想法对齐对话

本文档是把 `AI-youjiao-promax` 工作流产品化的第一版决策集合。每个决策都附带"为什么这么定"，便于后续动手对照、半年后回看 v2 时溯源、团队扩大时新人 onboarding。

---

## 0. 第一性原理（理解所有决策的根）

下面所有决策都从这四条第一性出发，而不是从功能特性出发：

1. **用户真正的目标 = 拿到让人眼前一亮的课件，去上一节好课**——不是"用 AI 提效"
2. **用户怎么思考 = 按线性 9 步走，不反复横跳**——横跳灵活但学习成本高，教研员学不会
3. **产品价值的锚 = 快速产出某知识点的完整课件（教案 + PPT + 导入视频）**——视频统称为课件的一部分
4. **闭环 = 用户拿到课件 + 系统记住偏好 + 越用越顺手**——飞轮是核心商业资产，不是锦上添花

所有后续决策的"为什么"都可以回溯到这四条。

## 1. 产品定位

### 1.1 一句话定义

把 `AI-youjiao-promax` 的 9 步公开课生产流程，从「宪法 + 散脚本 + 任务包目录」收口成一个**半自动化的、教研团队可用的网页产品**：用户结构化填写课题信息，AI 按字段化 schema 生成产物，用户在每一步通过"直接编辑"或"AI 重做"达到满意后 approve 进入下一步，最终交付可编辑 PPTX + 中文男声配音导入视频。

### 1.2 产品的核心卖点不是效率，是震撼力

用户不来是因为"AI 没做出让人眼前一亮的东西"。所以：
- 冷启动质量必须打满（教研员看一眼就觉得"卧槽这能用"）
- PPT 视觉元素要丰富，要有真实生活场景图（不是文本框 + 色块）
- 导入视频要有故事感、有钩子（不是 PPT 翻页录屏）
- 整体风格一致（PPT 和视频里的人物、配色、调性必须是一套）

### 1.3 目标用户

| 阶段 | 用户 | 模式 |
|---|---|---|
| v1 | 内部教研团队（有大量老师用户） | 本地部署，先打磨 |
| v1.x 外销 | 外部教研团队 / 个体教师 | 配套教程交付，客户自带 API key |

## 2. 产品形态

### 2.1 v1 交付面

**网页优先，智能体后置**。

教研内部用户对表单 + 文件树 + 审核面板这种 UI 接受度高；对话流形态等 v1 数据攒一段后再补。

### 2.2 v2+ 智能体形态

智能体和网页**共用同一份**：
- workflow_manifest 状态机
- 项目数据存储（SQLite + 文件系统）
- prompt 模板和规范文件
- 节点级 LLM provider 配置

智能体只是另一张 UI 皮，不是另一套数据后端。

---

## 3. 项目模型

### 3.1 项目边界

**一节课 = 一个项目 = 一个任务包目录**。

与现有 `工作流主包/任务包/{年级}_{学科}_{课题}_{用途}/` 契约完全对齐，迁移成本最小。

### 3.2 协作模式

**单人独立完成整个项目**。v1 不做：
- 节点级负责人 / 审批人
- 多人并发编辑锁
- 评论 / 讨论
- 操作审计日志（错误日志除外）

### 3.3 项目生命周期

| 状态 | 含义 | 用户可见 |
|---|---|---|
| 进行中 | 任一阶段 `not_started / drafted / needs_review / blocked` | 默认首页 |
| 已完成 | 收尾门禁通过、PPTX + 视频已交付 | 默认首页 |
| 已归档 | 用户主动归档 | 归档列表（默认折叠） |
| 已删除（软） | 用户主动删除 | 30 天回收站可恢复 |
| 已删除（硬） | 回收站 30 天后 | 不可恢复 |

## 4. 工作流主线

完全沿用 `执行规范/公开课自动化9步完整流程-Promax版.md` 定义的 9 步双分支结构，不重新发明：

```
第 0 步：项目配置（表单第一屏 + 角色字典 + 视觉契约）
第 1 步：公开课教案 [硬阻断]
第 1.5 步：导入设计选择集
        ├─ PPT 分支
        │   第 2 步：PPT 总装方案 [硬阻断]
        │   第 3 步：PPT 页面脚本（字段化 + 逐页审查智能体）
        │   第 4A 步：PPT 视觉资产
        │   第 7 步：ppt-master 生成 PPTX
        └─ 导入视频分支
            第 4B 步：导入视频文稿（用户需确认最终采用稿）
            第 4C 步：导入视频剧本
            第 5B 步：导入视频资产
            第 6 步：分镜 + 小云雀提示词
            第 8 步：视频生成 + 中文配音 + 拼接
收尾：最终交付门禁
```

### 4.1 节点可跳过

第 0 步表单勾选"不需要导入视频" → 第 4B-6、第 8 步整条分支自动置 `skipped` 状态，下游门禁不查这条分支。

manifest 状态机新增一个状态：`skipped`（区别于 `not_started`）。

## 5. 核心机制

### 5.1 函数式 pipeline 契约

每个节点定义为：

```
node_output = f(upstream_approved_outputs, specs, seed_params)
```

- `upstream_approved_outputs`：所有上游已 approved 的产物（按依赖图取）
- `specs`：`执行规范/` 下的规范文件
- `seed_params`：本次重做的种子参数（风格档位等）

**禁止读取**：旁路输入、未 approved 的草稿、其他分支的同级产物、外部不可控状态。

这条契约让 diff、影响分析、增量重生在数学上都是良定义的。

### 5.2 五状态机 + skipped

| 状态 | 含义 |
|---|---|
| not_started | 尚未开始 |
| drafted | AI 已生成草稿，未提交审查 |
| needs_review | 已提交审查，等待 approve |
| approved | 已确认，下游可读 |
| blocked | 缺资料 / 接口受限 / 质量不达标 |
| skipped | 用户主动跳过（v1 新增） |

### 5.3 重做 + 编辑双通道

进入下一步的两种通道：

| 通道 | 操作 | 结果 |
|---|---|---|
| 直接编辑 | 用户在网页字段表单 / Markdown 编辑器修改产物 | 保存为新版本，自动设为 current |
| AI 重做 | 用户调整种子参数 + 点重做 | AI 生成新版本，用户决定是否设为 current |

任一方式满意后点 approve 进入下一步。

### 5.4 连锁失效处理（v1 用方案 A）

任一节点的 current 版本变更（无论是编辑还是重做选了新版本）→ 所有下游已 approved 节点自动降级为 `needs_review`，UI 红点提示，用户挨个重审。

v2 升级到 diff 预览 + 影响分析。

## 6. 字段化 schema（v1 反幻觉的核心）

### 6.1 字段化 = 控制大模型边界

自由文本让 LLM 想填什么填什么，幻觉空间无限。字段化（带枚举、必填、字段间依赖）让 LLM 只能在定义的格子里写东西，**输出空间被结构性压缩 = 反幻觉**。

"前端结构化呈现给用户"和"控制大模型边界"是同一件事的两面。

### 6.2 不同节点不同粒度（按价值密度定）

| 节点 | 粒度 | 理由 |
|---|---|---|
| 教案 | 粗粒度 6 字段 | 老师一眼能判，是产线输入源不是终产物 |
| PPT 总装 | 中粒度 | 含页面类型配比约束 |
| PPT 页面脚本 | **细粒度 13 字段** | PPT 是最硬骨头，反幻觉必须强 |
| 视频文稿 | 粗粒度（v1.x 攻克） | v1 打通链路即可 |
| 视频剧本 | 粗粒度（v1.x 攻克） | 同上 |
| 视频分镜 | 中粒度（必填字段） | 直接喂 omni_flash，必须结构化 |
| 角色字典 | **必须细粒度** | 合规底线 + 视觉一致 |

### 6.3 教案 6 字段（粗粒度）

| 字段 | 备注 |
|---|---|
| 教材依据 | 版本 / 册次 / 单元 |
| 教学目标 | 单段文本 |
| 教学重难点 | 单段文本 |
| 教学流程 | 单段文本 |
| 板书设计 | 单段文本 |
| 三类九套导入设计 | **必须结构化**（下游第 1.5 步要按 ID 选择） |

后期可迭代加字段，加字段不破坏旧数据。

### 6.4 PPT 页面脚本 13 字段（细粒度，v1 全做）

调研结论：行业里没有"小学公开课专用 schema"，这套就是空白区，我们定就是标准。

| # | 字段 | 来源 |
|---|---|---|
| 1 | 核心素养锚点（11 选 1-2） | 新课标 2022 / 评议命中率最高 |
| 2 | 本页教学目标（≤30 字） | 通用必备 |
| 3 | 学生课堂动作（14 个动作词表选 1） | 现有规范 |
| 4 | 页面类型（11 类配比中选 1） | 总装方案约束 |
| 5 | 主视觉对象 + 服务目的 | 现有规范 + Mayer dual-coding |
| 6 | 角色字典引用 ID | 反幻觉关键 + 合规 |
| 7 | 待生图清单（生图描述 + 知识点关联 + 真实生活场景标签） | 用户要求"真实生活案例图" |
| 8 | 精确数学内容（公式 / 数字 / 单位 / 题面 / 答案） | "公式不能出错" + 反幻觉 |
| 9 | 任务区 / 数学区 / 结论区分区描述 | 现有规范 |
| 10 | 证据表达要求 | 现有规范 |
| 11 | 准确性提醒（教师备注层，不给学生看） | 现有规范 |
| 12 | 与上一页衔接 | 新增 |
| 13 | 信息密度限制（正文 ≤25 字 / 信息块 ≤5） | 认知负荷理论 / 6-12 岁特点 |

**PPT 总装方案配套约束**：新增"页面类型配比"字段（12 页里至少 1 页板书小结、1 页生活观察、2 页操作探究、2 页练习）。

### 6.5 视频分支字段（v1 最简版，v1.x 攻克）

视频是用户最期待解决的问题，但 v1 先打通链路，深度攻克放 v1.x。

**L1 视频整体（第 4B 步）**：时长 / 类型 / 课程锚点 / 旁白文本 / 禁用清单
**L2 剧本分场（第 4C 步）**：场次 / 时长 / 场景描述 / 角色引用 / 旁白
**L3 分镜逐镜头（第 6 步）**：编号 / 时长 / 画面主体 / 参考图 / 旁白切片 / 模型 prompt（v1 模板拼接）
**L4 角色字典**：见 6.6（v1 必须全做，合规底线）

v1.x 攻克项：节奏分配、情绪、数学元素显隐、景别 / 运动 / 多层元素清单、转场、prompt 自动拼装器。

### 6.6 角色字典（第 0 步定义，跨节点引用，v1 必须全做）

| 字段 | 作用 |
|---|---|
| 角色 ID（如 char_xiaoming） | 唯一标识 |
| 名字 + 身份 | 上下文 |
| 多视角描述（正面 / 侧面 / 背面 / 半身 / 手部特写） | 一致性 + 合规 |
| 服装锁定（颜色 / 款式 / 配饰） | 一致性 |
| 发型锁定 | 一致性 |
| 体型 / 比例 | 一致性 |
| 风格约束（卡通 / 剪影 / 3D / 不写实） | 合规 + 视觉一致 |
| **禁用关键词（真人 / photorealistic / 真实儿童）** | 合规硬约束 |
| 参考图（如有） | 模型契约 |

角色字典的存在解决了肖像权问题：通过"多视角描述 + 服装发型锁定 + 风格非写实约束"，规避真人未成年人。

## 7. 表单层固定字段（第 0 步表单）

### 7.1 A 档：必填，单选 / 下拉

| 字段 | 选项 |
|---|---|
| 学科 | 数学（v1 仅此） |
| 年级 | 1-6 |
| 教材版本 | 人教版 / 北师大版 / 苏教版 / 西师大版 / 其他 |
| 册次 | 上册 / 下册 |

### 7.2 B 档：有默认值，用户可改

| 字段 | 默认 |
|---|---|
| 是否需要导入视频 | 是 |
| 视频交付类型 | 完整短片 60-120s |
| PPT 目标页数范围 | 12-16 |
| 视觉丰富度 | 中 |
| 是否嵌入视频 | 否 |
| 视频类型范围 | 全部（科普 / 应用 / 故事） |
| 每类方案数量 | 3（= 三类九套） |

### 7.3 C 档：产品红线，UI 不给开关

| 字段 | 锁定值 |
|---|---|
| 中文旁白 | 是 |
| 中文男声 | 是 |
| 禁英文配音 | 是 |
| 禁真人感未成年人 | 是 |
| 单段冒充完整视频 | 阻断 |
| 候选冒充终版 | 阻断 |

### 7.4 D 档：项目级偏好文本框（可空）

- 必须 PPT 可编辑层的内容
- 禁止交给图片/视频生成的内容
- 必须保留的板书 / 公式
- 特殊要求
- 禁止事项
- 补充资料上传

### 7.5 E 档：角色字典 + 视觉契约（第 0 步必填）

详见 6.6。视觉契约 token 字段：
- 主配色（3-5 色）
- 视觉风格关键词（扁平 / 立体 / 手绘 / 渐变）
- 字体偏好

PPT 视觉资产和导入视频资产都读这一份，跨分支视觉一致。

### 7.6 F 档：对标 PPT（可选上传）

用户可上传外部 PPT 作为风格参考。v1 用现有 skill 实现（不重复造轮子，待调研选型）。

支持深度（v1 起步层）：提取色彩 + 字体 + 版式（视觉风格抄过来）。v1.x 升级到提取页面结构 / 教学法 / 风格融入飞轮。

### 7.7 G 档：高级模式才显示（v1 默认隐藏）

图片默认尺寸、画幅、质量、生图模型、并发数量、输出根目录、API 字段等。

## 8. 多模型策略

### 8.1 默认 provider 配置

| 用途 | 模型 |
|---|---|
| 教案分析、文稿生成、剧本 | DeepSeek |
| 链路监督 / QA / 逐页审查智能体 | Claude |
| 通用执行 | GPT |
| 生图 | gpt-image-2 |
| 视频 | omni_flash-10s（兜底 sora-2-12s） |
| 中文 TTS | 待定 |

### 8.2 抽象层设计

代码层面**任何 LLM/API 调用都必须经过统一抽象**：

```
LLMProvider 接口
  ├─ DeepSeekProvider
  ├─ ClaudeProvider
  ├─ GPTProvider
  └─ ...

NodeConfig {
  node_id: str
  default_provider: str       # "deepseek"
  fallback_provider: str      # "gpt"
  user_override: str | null   # 用户在 UI 改的
}
```

UI 上每个节点提供 provider 切换下拉。

### 8.3 prompt 跨模型适配

每个节点的 prompt 要在每个候选 provider 上验证过。可能需要"节点 × provider"的 prompt 矩阵。

v1 范围：每个节点至少在 default + fallback 两个 provider 上跑过，质量持平。

### 8.4 失败降级

- 默认 provider 失败 → 自动重试 2 次（指数退避）
- 仍失败 → 自动切 fallback provider
- 切了 fallback → UI 明确提示"本次用了备用模型 X，可回滚重做"

### 8.5 成本可见

重做按钮触发前显示预估成本：

```
重做第 1 步教案
  默认（DeepSeek）：约 ¥0.05
  改用 Claude：约 ¥1.20
[确认重做]
```

每个项目维护成本累计统计。

### 8.6 密钥管理

抽象出 KeySource：

| 模式 | 来源 |
|---|---|
| 内部模式 | 环境变量 / 配置文件 |
| 外销模式 | 客户在系统设置里录入自己的 key |

v1 同时支持，启动时配置切换。

## 9. 逐页审查智能体（PPT 节点专属）

### 9.1 机制

第 3 步 PPT 页面脚本生成时，**每生成一页立刻跑审查智能体**：

```
AI 生成第 N 页脚本
  ↓
逐页审查智能体（Claude）跑：
  - 13 个字段是否合规填写
  - 是否符合 PPT 探究型约束
  - 主视觉描述是否能被生图模型稳定生成
  - 数学准确性
  - 与上一页衔接
  - 是否引用了角色字典里的角色
  ↓
不合格 → 立刻打回重生（不进入用户视野）
合格 → 展示给用户审核
  ↓
用户编辑 / 重做 / approve → 进入下一页
```

**避免"做完 12 页发现整体不对，全部推倒"的灾难**。

### 9.2 审查标准来源

单独写一份"逐页审查标准"文档（不是直接复用规范）。每条标准带：
- 严重程度（阻断 / 警告 / 提示）
- 触发条件
- 建议措施

### 9.3 用户可 override

按"绝对主导权"原则，用户可强制 approve 不合格页。但 override 会被记录到飞轮（"哪条规则被这位用户最常 override"）。

### 9.4 模型选型

Claude 跑审查。每页都跑成本会上去，可做"轻量版逐页 + 重量版每 4 页汇总"两级。

### 9.5 v1 范围

只在 PPT 节点做。教案、文稿、剧本等不做（验证有效后再推广）。

## 10. 飞轮（核心商业资产）

### 10.1 飞轮信号源（三类）

| 信号 | 来源 | 价值 |
|---|---|---|
| 用户在第几版 approve | 重做版本历史 | 偏好方向 |
| approve 后又手动改了哪些段落 | 编辑 diff | 精修信号（最高价值） |
| 课件到手反馈 + 上完课反馈 | 用户主动填写 | 终极信号 |
| 审查智能体被 override 的规则 | override 记录 | 个人化偏好 |

### 10.2 反馈机制

**课件到手反馈**：交付完成时弹窗
**上完课反馈**：**用户第二次使用产品（做下一节课时）弹窗**

第二次使用弹窗的理由：
- 不打断当前流程
- 用户真正用过后才有反馈价值
- 用户已经回来做下一节课 = 产品有粘性 = 反馈率更高

### 10.3 v1 极简实现

- 不训练、不微调
- 检索逻辑：当前节点重做时，从 SQLite 取该用户最近 3 个**已 approved 的同节点产物**片段，拼接到 prompt 的"参考已通过样例"区
- 隐私：v1 不跨用户检索

### 10.4 偏好画像可视化（v1 必做）

让用户能看到"系统理解的我"，否则黏性感受不到。

形态：参考成熟用户画像调研产品的可视化做法（不发明新形态）：
- 证据收集
- 标签化
- 可视化（雷达图 + 关键词标签 + 行为证据列表）

v1 展示维度（最小集合）：
- 风格偏好（生活情境 / 数学情境 / 历史科普）
- 详略偏好（精炼 / 适中 / 详细）
- 探究强度偏好（保守 / 平衡 / 激进）
- 模型偏好（DeepSeek / Claude / GPT 使用频率）
- 课题领域偏好（几何 / 运算 / 应用题 / ...）

### 10.5 跨设备偏好同步

切换设备 / 重新登录 / 换浏览器，偏好必须跟着走。

v1 内部用：用户账号关联偏好。
外销时：客户账号体系打通。

## 12. 视频生成专用机制

### 12.1 单镜头先测一帧（必做）

正式调 omni_flash 之前，先用生图模型出"这个镜头的首帧"——审通过了才花钱跑 10s 视频。

省钱关键：10s omni_flash 一段几块钱，6 段就是几十块。先出首帧（几毛钱）审过再跑视频，浪费率降 80%。

### 12.2 6 段并发 + 失败重试（已在 P0）

并发跑（不串行），每段独立 task_id。任一段失败：
- 单独重试（不重跑成功的 5 段）
- UI 显示每段进度
- 部分失败可接受（用户选跳过失败段或重生）

### 12.3 拼接前的逐镜头审查（必做）

6 段都跑出来后，**拼接前**用户逐段审：
- 时长是否对
- 画面是否符合 prompt
- 角色一致性是否守住
- 衔接是否流畅

全过审才进入拼接 + 中文男声 TTS + 字幕合成。

### 12.4 prompt 自动拼装器（v1.x）

L3 字段→prompt 的自动拼装。v1 用模板字符串拼接即可。

## 13. 存储层

### 13.1 v1 方案：SQLite + 文件系统混合

```
{输出根目录}/
  项目A_认识周长_20260618/
    project.db              # SQLite 单文件
    assets/

        visual_frame_01.png
```

### 13.2 SQLite 表设计范围

| 表 | 内容 |
|---|---|
| project_meta | 项目元数据 |
| manifest | workflow_manifest 结构化版本 |
| node_versions | 每节点所有版本的字段化产物（不只是 Markdown，是 JSON 字段） |
| node_current | 每节点当前 current 版本指针 |
| seed_history | 用户用过的种子参数（飞轮数据源） |

| post_approve_edits | approve 后又被手动编辑的 diff |
| override_history | 用户 override 审查智能体的记录 |
| error_log | 错误事件流 |
| cost_log | 每次调用的 token / 成本统计 |

| feedback_log | 课件到手 + 上完课反馈 |

### 13.3 文件系统存什么

- 真二进制：png、mp4、wav、pptx、svg、pdf、srt
- 路径记录在 `node_versions.assets_path`

### 13.4 备份 / 导出

- 整个项目目录 zip = 完整可移植项目
- 启动时跑 SQLite integrity check

### 13.5 演进路径

v1 → 云端 SaaS：SQLite schema 直接迁 Postgres，assets 迁对象存储。代码层因为存储抽象接口，业务逻辑不动。

## 14. 错误处理

### 14.1 错误处理哲学

内部工具：错误可以"扔出来"。
对外产品：错误必须**被产品消化掉**。

每个失败点必须想清楚三件事：**用户看到什么、用户能做什么、用户的钱/数据有没有损失**。

### 14.2 错误分四大类

#### A. AI 模型层错误

| 子类 | v1 策略 |
|---|---|
| 超时 | 自动重试 2 次（指数退避）→ 切 fallback → 仍失败弹"暂时不可用" |
| 限流 | 自动重试 + 提示"当前并发高" |
| 内容拒答 | 不重试 → 弹"建议改种子参数或换模型" |
| 输出格式错 | 自动重试 1 次（强化 prompt）→ 仍失败按文本兜底解析 |
| 质量崩 | 用户主动重做 |
| 服务不可用 | 自动切 fallback → 失败则保存进度 |

关键设计点：
- 重试要可见（UI 显示 "重试中 (2/3)..."）
- 降级要透明（明确告诉用户用了备用模型）
- 失败不计费

#### B. 外部资源失败

异步任务系统是 v1 必做：

```
用户点"生成 6 段视频"
  → 立刻返回任务 ID
  → UI 显示"已提交 6 个任务，预计 5 分钟"
  → 用户可关网页
  → 完成后站内通知 + 失败的单独标红
  → 失败的可单独重试
```

每段视频独立保存 + manifest 记录 task_id / 状态 → 断点续跑。
部分失败可接受 → 用户可选择跳过失败段。
资源校验前置 → 提交前检查 key 有效性、额度。

#### C. 用户操作错误

| 子类 | v1 策略 |
|---|---|
| 误删项目 | 软删除 30 天回收站 |
| 误覆盖产物 | 版本留痕兜住 |
| 必填字段缺失 | 前端 + 后端双校验 |
| Markdown 格式破坏 | 保存时校验能否被下游正确读取 |
| 多标签操作 | 检测并提示"建议只开一个窗口" |
| 路径非法字符 | slug 化处理 |

#### D. 系统级错误

| 子类 | v1 策略 |
|---|---|
| 磁盘满 | 启动检查 + 每次大写入前检查 + 阈值预警 |
| 数据库损坏 | 每次操作自动备份 SQLite + 启动 integrity check |
| 进程崩溃 | 关键操作 atomic 写入（临时文件 → rename） |
| 数据迁移 | 升级前自动备份整个项目目录 |

### 14.3 三个支撑机制

**全局错误日志**——`error_log` 表 + `errors.log`。用户可一键打包脱敏后的日志 + 项目快照反馈。

**自动保存草稿**——编辑产物每 N 秒落盘草稿，崩了重开还在。

**操作可逆**——破坏性操作：二次确认 → 10 秒内可一键撤销 → 撤销期过仍可从回收站 / 版本历史找回。

### 14.4 UI 三原则

1. **状态可见**：耗时 > 2 秒的操作必须有进度提示
2. **失败可懂**：错误信息说人话，不暴露 HTTP code 或 stack
3. **总有出路**：每个错误页面给至少一个"用户能做的下一步"

### 14.5 v1 投入优先级

| 优先级 | 项 |
|---|---|
| P0（必须） | AI 自动重试、异步任务系统、断点续跑、版本留痕、软删除、错误日志、状态可见 UI |
| P1（强烈推荐） | provider 自动降级、自动保存草稿、操作撤销、磁盘预警、key 失效预检 |
| P2（v1.x 补） | SQLite 自动备份、内容拒答智能处理、一键反馈打包 |

## 15. 产品红线（合规硬约束）

UI 不给开关、绝对主导权也不能凌驾：

1. 中文旁白 + 中文男声 + 禁英文配音
2. 视频必须多分镜拼接（单段 omni_flash-10s 自动判定为素材不是终版）
3. 禁真人感未成年人 / 禁可识别儿童脸 / 禁真实课堂实拍感（**靠角色字典 + 多视角 + 服装锁定 + 非写实风格规避**）
4. 候选与终版严格区分
5. 现有门禁脚本（`final_delivery_gate.py` / `workflow_contract_gate.py` / `videogen_batch_jobs.py validate` / `audit_*.py`）原样接进 v1 流程
6. PPT 必须包含课程视觉资产

## 16. AI 味（长期风险，v1 不专门做）

教研评议时"看着像 AI 写的"是减分项。

v1 不专门做"去 AI 味"。理由：
- 飞轮跑起来后会自然减轻（用户改得越多 AI 越接近用户风格）
- 真正的去 AI 味方案（rewrite + 多模型轮换 + 高频词剔除）是独立项目，等 v1 数据攒够再说

**v1 唯一动作**：飞轮设计要鼓励"用户改 AI 的版本"而不是"用户接受 AI 的版本"——前者沉淀去 AI 味信号，后者沉淀 AI 味本身。

## 18. v1 验收标准

**最小可爱用例**：

> 一位教研员打开网页 → 填表单（课题 + 年级 + 教材版本 + 课型 + 角色字典 + 视觉契约）→ 第 1 步教案草稿生成（6 字段） → 看了不满意，调档位重做 / 或直接编辑 → approve → ... → 第 3 步 PPT 页面脚本逐页生成 + 逐页审查智能体把关 → ... → 第 8 步视频先出首帧审过 → 6 段并发跑 → 拼接 → 第 9 步交付 → 弹窗"课件到手反馈"。

**回头修复用例**：

> 走到第 4B 步时教研员回头改了第 1 步教案 → 下游所有 approved 节点正确变红 → 教研员逐个重做 / 重审走完 → 最终交付门禁通过。

**异常容错用例**：

> 6 段视频生成时第 3 段 omni_flash 失败 → UI 显示其余 5 段已完成、第 3 段失败可单独重试 → 用户重试成功 → 拼接 → 通过最终门禁。

**飞轮初见用例**：

> 教研员做完第二节课时，弹窗"上完课反馈"——填了"上节课学生反应不错" → 飞轮记录 → 这位教研员的"偏好画像"页面更新 → 第三节课的 AI 生成草稿更贴近他风格。
