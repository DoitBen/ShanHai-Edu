# ShanHaiEdu 项目共享事实

## 当前产品定位

- 项目名称：ShanHaiEdu。
- 当前定位待继续细化：围绕教育内容生产、教材解析、教案生成、视频文稿、剧本和分镜生成等能力，服务教育内容生产与教学资源创作场景。

## 用户画像

- v1 核心用户画像档案位于 `workflow\multi-agent\user-personas.md`，所有角色启动时必读。
- 主画像 P01：李雪老师（地级市小学数学骨干教师，备区级公开课冲职称），所有功能优先满足该画像。
- 次画像 P02：王教研员（v1.x 扩展用户，v1 不优先服务）。
- 反画像清单已列出，不为以下用户做妥协：大学/培训机构/初高中教师、农村教学点、AI 产品同行尝鲜。

## 当前协作机制

- 本项目采用本地多角色协作模式，当前机制版本为 V0.3 闭环版。
- 当前机制已升级为 V0.4 总控闭环：重要任务遵循“架构师下发 → 专业角色交付 → 测试工程师验收 → 架构师对照原任务、交付物、测试报告和关键代码/配置 diff 复核 → 通过或再调度”。
- 用户可在任意新对话中用自然口令手动指定角色，例如“你是前端工程师”“你是前端开发”“你是系统架构师”“你是产品经理”“你是测试”“你是运维”。
- 每个角色需要先读取项目级规则、本机制说明、角色调用模板、交付物模板、共享事实、对应角色记忆和最近交接记录。
- 每轮重要工作结束后，需要更新对应角色记忆和交接记录；涉及重要结论、跨角色冲突或阶段推进时，还需要更新决策台账、冲突台账或阶段总控记录。

## 已确认角色

- 首席系统架构师：全局统筹、跨角色协调、边界裁决、阶段规划。
- 产品经理：产品定位、网站业务功能、用户价值、市场与用户需求、业务流程、验收标准。
- 高级 UI 设计大师 + 前端工程师：UI/UX 设计、页面体验、交互路径、视觉一致性、前端体验落地。
- 高级后端工程师：后端能力、服务规则、权限安全、稳定性与可维护性。
- 全项目测试工程师：业务流程、界面交互、权限角色、边界异常、性能安全等质量验收。
- 运维/部署工程师：环境变量、密钥注入、容器部署、日志、备份、健康检查和回滚；不实现后端业务接口，不替代测试验收。

## 已确认需求

- 建立“角色对话 + 角色记忆 + 项目共享事实 + 交接记录”的本地协作模式。
- 支持用户通过“你是某某角色”或自然别名手动指定当前对话角色。
- 保证后续新对话可通过读取角色记忆和交接记录继续接手。
- 建立角色调用模板和交付物模板，降低每次启动和交付的格式漂移。
- 建立决策台账、冲突台账和阶段总控记录，形成可追溯闭环。
- 新增运维/部署工程师作为开发团队固定角色，补齐部署、运行、密钥、日志、备份和回滚职责。
- 前端首屏性能基线：`AppShell` 不静态引入业务大页和 `CommandPalette`，业务 screen 采用 `next/dynamic` 按需加载，命令面板仅打开时挂载。
- 前端设计语言基线：当前采用暖纸白、深青灰、古铜金的教研工作台体系，设计依据以 `docs\FRONTEND_DESIGN.md` 和 `apps\web\src\app\globals.css` 为准。
- 新建项目体验基线：项目创建必须包含角色字典、视觉契约和合规红线，作为 PPT 与导入视频的共同上下文。
- 导入视频产品基线：如果本课需要导入视频，教案中的导入设计必须拆成"导入视频策划卡 + 课堂接入说明"两层；导入视频和教案之间唯一硬连接字段为课程锚点。课程锚点只负责把独立、有吸引力的视频主题自然接回本课学习任务，不负责提前讲解知识点；导入视频不得被教案限制成知识讲解。
- 前端本地真实 API 演示基线：`NEXT_PUBLIC_DEMO_MODE=false` 时，项目列表、创建项目、工作区 manifest、节点详情、`textbook_parse` 生成和确认走后端 API；默认 demo/mock 模式继续隔离使用 mock 数据，不与真实 API 状态混用。

## 已拒绝或暂不采用

- 暂不采用所有角色在同一对话中无限自由讨论的模式。
- 暂不追求全自动多智能体编排，优先建立手动指定角色的最小可用机制。

## 待决策问题

- 是否需要为每个角色建立独立的固定对话标题和命名规范。
- 是否需要设置阶段例会式的固定节奏。
- 是否需要设计跨角色审阅顺序。
- 部署路线待首席系统架构师裁决：当前阶段优先补 docker-compose/内网最小部署，还是直接按 Cloud Run 约束推进。
- 当前部署路线已裁决：优先补 docker-compose/内网最小部署，Cloud Run/云端部署后置为后续专题。

## 当前部署基线

- 最小运维 Runbook 草案位于 `docs\ops-runbook-draft.md`。
- Web 本地开发目录为 `apps\web`，开发启动命令为 `bun run dev`，默认端口 `3000`。
- Web 构建与生产启动命令为 `bun run build`、`bun run start`，Next 配置使用 standalone 输出。
- API 从仓库根目录启动：`uvicorn apps.api.app.main:app --reload --port 8000`，默认端口 `8000`。
- API 健康检查为 `GET /health`，默认 provider 模式为 `PROVIDER_MODE=fake`。
- API 默认 runtime 数据根目录为 `storage`，项目数据位于 `storage\projects\<project_slug>_<project_id>\`，包含项目 SQLite、上传文件、生成资产和项目级日志。
- 真实 provider 密钥只能注入后端运行环境，禁止写入前端、源码、日志或提交信息。
- 当前仓库未发现正式 Dockerfile、docker-compose/compose 文件；API 已补 `apps\api\.env.example` 和 `apps\api\requirements.txt`，可支撑本地演示复现。
- 后续部署推进顺序：后端先补运行契约和依赖清单，运维再补 Dockerfile/compose/`.dockerignore`/storage volume/健康检查/回滚草案，测试最后做新人冷启动和端到端部署验收。
- 真实 provider 演示 Runbook 位于 `docs\ops-real-provider-demo-runbook.md`。
- 真实文本链路由 `PROVIDER_MODE` 控制，真实视频链路由 `VIDEO_PROVIDER_MODE` 控制；推荐完整 E2E 用 `PROVIDER_MODE=real` + `VIDEO_PROVIDER_MODE=placeholder`，真实 Octo 视频单独 smoke。
- 生图 provider 当前由项目内 `skills\imagegen-myself` 脚本负责，不是 `apps\api` 内建 endpoint；真实生图产物不得提交。
- 当前后端合成真实多 clip 视频时从 `PATH` 查找 `ffmpeg`，`FFMPEG_PATH` 仍是运维预留变量。

## 统一验收口径

- 用户说出角色身份后，该角色能知道该读取哪些文件。
- 角色能在自己的职责边界内工作，不越权输出。
- 角色工作结束后能更新对应记忆和交接记录。
- 重要结论能进入决策台账。
- 跨角色分歧能进入冲突台账。
- 阶段结束能进入阶段总控记录。
- 新对话读取共享事实、角色记忆和最近交接后，可以继续推进项目。
