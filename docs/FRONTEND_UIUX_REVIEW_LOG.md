## 3. 主要问题

### P1：新建项目不完整承载第 0 步核心配置（已处理）

PRD 要求第 0 步包含项目配置、角色字典和视觉契约。当前新建项目页主要覆盖基础信息、教材上传、视频方向、PPT 配置、输出路径与安全模式，缺少以下关键输入：

- 角色字典：角色 ID、外观锁定、多视角描述、非写实约束、禁用关键词。
- 视觉契约：主配色、视觉风格关键词、字体偏好、PPT 与视频共享风格 token。
- 合规红线的明确展示：禁真人未成年人、禁英文配音、中文男声、多分镜终版等。

影响：用户创建项目时没有把“PPT 与视频视觉一致性”和“合规红线”作为项目级上下文固化，后续节点容易靠补丁式提示维持一致性。

处理结果：已在新建项目基础信息步骤内新增“第 0 步核心配置”，覆盖角色字典描述、角色安全规则、主配色、视觉风格关键词、字体偏好和合规红线；创建流程校验和配置摘要已同步纳入这些字段。

### P1：设计语言文档与实现不一致（已处理）

`docs\FRONTEND_DESIGN.md` 描述的是深海蓝企业工作台，默认背景为 `#0A0F1E`；而 `apps\web\src\app\globals.css` 当前实现为暖纸白、深青灰、古铜金体系。

影响：后续前端开发会缺少统一依据，同类页面可能继续分裂成深色工作台和暖纸白教研工作台两套语言。

处理结果：已重写 `docs\FRONTEND_DESIGN.md`，统一为暖纸白、深青灰、古铜金的教研工作台设计语言，并补充组件、页面、交互、性能和验收口径。

### P1：演示凭据直接出现在界面和客户端逻辑中（已处理）

发现位置：

- `apps\web\src\components\layout\AppShell.tsx`
- `apps\web\src\components\screens\LoginScreen.tsx`
- `apps\web\src\lib\store.ts`

原页面和代码中可见 `admin / shanhai2026`、`teacher / shanhai2026`。

影响：演示阶段可接受，但正式交付、截图评审或客户试用时会显得临时，也会降低安全可信度。

处理结果：已新增演示模式工具，`NEXT_PUBLIC_DEMO_MODE=false` 时隐藏演示账号提示并禁用演示账号登录；演示密码集中到单一常量，UI 不再散落硬编码密码。生产级认证仍属于后续后端/安全改造范围。

### P1：工作区节点操作区主次不清（已处理）

项目工作区底部同时展示：

- 保存
- 重新生成
- 退回修改
- 进入下一步
- 确认通过

影响：教研员面对线性 9 步流程时，会不知道当前最应该点哪个；尤其“进入下一步”和“确认通过”并列时，容易造成语义重复。

处理结果：工作区底部操作区已调整为保存、重新生成、退回修改等辅助动作 + 一个随状态变化的最高权重主 CTA：

- 未生成：生成草稿
- 生成中：查看运行状态 / 取消
- 待确认：确认通过
- 已通过：进入下一步
- 异常：重试 / 查看日志

其他动作降为次级按钮或更多菜单。

### P2：移动端和窄屏布局存在待复核风险（待复核）

源码中 Stepper、Tabs、对比弹窗、能力表格、证据预览等位置使用横向滚动或较大最小宽度。由于本轮没有成功获取 390 / 768 截图，暂不判定为发布阻断，但需要补测。

建议：后续至少在 1440 / 1280 / 1024 / 768 / 390 五个宽度下验证：

- 是否出现影响主任务的横向滚动条。
- 按钮组换行后是否对齐。
- 弹窗关闭、保存、确认按钮是否可达。
- 表格和对比面板在手机宽度下是否仍有可理解的替代呈现。
