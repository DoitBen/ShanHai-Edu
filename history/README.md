# 产品开发历程

这里是 AI-youjiao 半自动化工作流产品从"屎山规范"到"可执行基线"的完整决策历程档案。

## 用途

- **新人 onboarding**：读完能理解每个决策"为什么是这样"，不只是"是什么"
- **半年后回顾**：当 v2 决策需要溯源时，能找到 v1 当时的取舍逻辑
- **复盘**：哪些判断对了、哪些后来证明错了
- **资本沟通**：投资人/合作伙伴问"为什么选这条技术路线"时，这里有完整推演

## 档案清单

| 文件 | 内容 |
|---|---|
| `00_决策时间线.md` | 按时间顺序记录每个关键决策点 |
| `01_产品定位演进.md` | "AI 自动跑通" → "半自动化 + 主导权 + 飞轮"的形态转变 |
| `02_关键拐点.md` | 几个改变方向的关键讨论瞬间 |
| `03_为什么这样设计.md` | 重要设计决策的"为什么" |
| `04_拒绝过的方案.md` | 讨论过但放弃的路线，含原因 |
| `05_风险与不确定性.md` | 已识别风险 / 未解开放问题 / 未来要验证的假设 |
| `06_团队与角色.md` | 谁参与了哪些决策 / 谁负责什么 |
| `07_对话精华.md` | 关键讨论的原话节选（含情绪和判断风格） |

## 阅读顺序建议

- 5 分钟版：只读 `00_决策时间线.md`
- 30 分钟版：加 `01_产品定位演进.md` + `02_关键拐点.md`
- 完整版：按顺序读 8 份

## 与其他文档的关系

```
产品开发历程/        ← 为什么这样做（历史 + 取舍）
  ↓
v1_产品决策记录.md   ← 决定了做什么（产品 PRD）
  ↓
v1_技术路线规划.md   ← 怎么做（开发实施）
  ↓
半自动化工作流/      ← 真正的执行基线（机器可读）
```

四份合在一起 = 完整产品语境。

## 维护原则

- **不是会议纪要**：不记录"今天讨论了什么"，记录"得出了什么判断、为什么"
- **不删旧版**：决策反转时新增条目说明"以前认为 X，现在认为 Y，原因 Z"
- **保留情绪**：当时的犹豫、担心、确信，对未来回看有用
- **可追溯**：每条决策标注日期，便于查上下文
