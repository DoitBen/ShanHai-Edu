# AI-youjiao 半自动化工作流

版本：2026-06-18 v1
定位：把小学数学公开课的 AI 生产流程从「宪法 + 散脚本 + 任务包目录」收口成一个可被产品消费的纯净规范集。

## 这是什么

四份文档 + 一个 prompt 目录，构成 v1 产品的 source of truth：

| 文件 | 角色 | 谁读 |
|---|---|---|
| `schema.md` | 数据结构定义（节点字段 / 角色字典 / 项目元数据） | 后端建表、前端建表单、AI 生成时填字段 |
| `state_machine.md` | 状态流转规则（五状态 + skipped + 连锁失效） | 后端状态引擎 |
| `rules.md` | 机器可验规则登记表（一条规则一行） | 审查智能体、门禁脚本 |
| `prompts/` | 节点 × provider 的 prompt 模板 | LLM 调用层 |

## 为什么重构

原 `执行规范/` 14 份文档是 prompt 工程时代的产物——把规则、教学法、状态机、数据 schema、给人的提示揉在一起塞给 AI。对全自动跑通有效，对半自动产品有害：

- 编号体系崩了（两个"第二步"、`08_/08A_/08B_` 三套并存、新旧目录共存）
- 同一概念多种叫法（导入视频 = 短视频 = 短导入片 = 完整教学视频）
- 9 个门禁脚本是 9 个补丁
- 给人的话和给机器的契约混在一段 Markdown 里
- 改一条规则要动 3 处文件，相互不一致

v1 要做的事：**字段化反幻觉 + 状态机驱动 + 飞轮沉淀**。这三件事都需要纯净的、机器可读的输入。

## 设计原则

1. **数据归数据，规则归规则，prompt 归 prompt**——不再混写
2. **每个事实只在一个地方定义**——schema 字段在 schema.md、规则在 rules.md，其他文档只引用
3. **机器可读优先**——schema 用表格、规则用结构化条目、状态机用状态转换表
4. **教学法建议进 prompt，不进规则**——给 AI 的提示放进 prompts/，不污染状态机和 schema

## 与原规范的关系

- 原 `执行规范/` 14 份 + `工作流主包/` 不再作为产品输入
- 它们的有效内容已经被提炼到这四份文档
- 原文件保留在 `执行规范/` 和 `工作流主包/`，作为历史叙事和教学法素材库
- v1 产品代码只读本目录

## 阅读顺序

新人 onboarding：`README.md`（你在这）→ `schema.md` → `state_machine.md` → `rules.md` → `prompts/`

开发对照：先看 `schema.md` 建表，再看 `state_machine.md` 写状态引擎，再看 `rules.md` 写审查智能体，最后看 `prompts/` 写 LLM 调用层。

## 工作流核心：9 步双分支

```
第 0 步  项目配置 + 角色字典 + 视觉契约
   ↓
第 1 步  公开课教案
   ↓
   ├── 第 2 步  PPT 总装方案
   │      ↓
   │   第 3 步  PPT 页面脚本（13 字段 / 逐页审查智能体）
   │      ↓
   │   第 5A 步  PPT 视觉资产（生图）
   │      ↓
   │   第 7 步   ppt-master 装配 PPTX
   │
   └── 第 1.5 步 导入设计选择集
          ↓
       第 4B 步  导入视频文稿
          ↓
       第 4C 步  导入视频剧本
          ↓
       第 5B 步  导入视频资产（生图）
          ↓
       第 6 步   分镜脚本
          ↓
       第 8 步   视频生成 + 中文旁白 + 拼接
   ↓
第 9 步  最终交付（PPT + 视频 + 反馈弹窗触发器）
```

PPT 分支与导入视频分支并行，只在第 7 步装配处合流（视频可嵌入 PPT 开头）。

## 产品红线（不可被规则推翻、不可被用户编辑）

1. 中文旁白，禁英文配音；配音性别可配置，不作为硬阻断
2. 视频禁真人感未成年、禁可识别儿童脸、禁真实课堂实拍感
3. 完整视频必须多分镜拼接，单段 omni_flash-10s 自动判定为素材不是终版
4. 候选不能伪装终版，`--mode candidate` ≠ `--mode final`
5. 角色字典中"禁真人 / photorealistic"是硬约束，不可关
6. 数学事实必须进可编辑文本层，不交给图片/视频模型生成

红线在 `rules.md` 里以 `severity=hard_block` 标记，命中即阻断流程，无 override 选项；配音质量类提醒为 warning，可记录原因后覆盖。
