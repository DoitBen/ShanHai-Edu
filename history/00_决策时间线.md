## 2026-06-18

### 18:30 区分"工作流"和"临时产物"
- 决策：归档 6 套真实生产测试任务包 + 全部 .bak 文件到 `AI-youjiao-promax_archive_20260618/`
- 理由：开始重构前必须把"工作流规范"和"历史跑出来的产物"分干净，否则下面所有讨论都会被噪声干扰
- 影响：原 `任务包/` 全部移出，产品规范层从此独立

### 19:00 第一次提"半自动化"
- 决策：放弃"完全自动化"目标，承认教学法判断不可自动化
- 理由：原工作流的 9 步硬阻断 + 8 个门禁脚本本身在自证完全自动化不可行
- 影响：所有后续设计都假设"AI 出草稿 + 人审 + 通过/重生 + 下一步"

### 19:30 锁定 4 条第一性
- 决策：用户目标 / 用户思考方式 / 产品价值锚 / 闭环 四个第一性
- 理由：避免后续讨论被"AI 提效"这种空话带偏
- 影响：所有决策可回溯到这四条

### 20:00 PPT 字段化（13 字段细粒度）
- 决策：PPT 页面脚本走最细粒度
- 理由：用户说"PPT 不消耗 token"——意思是字段定义是结构，不烧 token
- 影响：JSON Schema 复杂度 80% 集中在 ppt_page_script

### 20:30 视频 v1 最简版 + v1.x 攻克
- 决策：视频是"最期待解决"但 v1 先打通链路
- 理由：MVP 边界是"端到端跑通"，视频深度调优放下个版本
- 影响：storyboard schema 只留必填字段，prompt 自动拼装器推后

### 21:00 角色字典 = 合规底线 + 视觉一致性
- 决策：角色字典必须细粒度（多视角 + 服装锁定 + 禁真人）
- 理由：用户提出"约定死了角色各视角描述就不会侵权"——这是关键洞察
- 影响：合规问题从"需要审核团队"变成"schema 字段约束"

### 21:30 五个风险点的 A/B/C/D 阶梯方案
- 决策：每个产品风险点都设计成"先做最笨的、听用户抱怨再升级"
- 涵盖：种子可见 / 版本留痕 / 连锁失效 / 教程 / 飞轮
- 影响：v1 不过度设计，留升级路径

### 22:00 编辑下游连锁失效用方案 A
- 决策：上游变 → 下游所有 approved 一键降级
- 理由：用户接受"自己重审"，绝对不接受"系统暗中失效"
- 影响：用户信任感的底座

### 22:30 第一版 PRD 完成
- 决策：v1 产品决策记录 v1.0 写完（539 行）
- 内容：5 个设计点起步配置 + 字段表单 ABCDE 档 + 多模型策略 + 错误处理 P0/P1/P2
- 状态：被 23:00 后的"震撼力 + 飞轮"讨论扩展为 v2

### 23:00 重构第一性：从"效率"到"震撼力"
- 决策：用户来不是为效率，是为"眼前一亮"的课件
