# 产品定位演进

记录产品"是什么"的判断如何变化。每次变化都改变了后续所有设计。

---

## 阶段 1：原始定位（讨论之前）

**定位**：把小学数学公开课的 prompt 工程标准化、规范化、可追溯

**特征**：
- 14 份执行规范
- 9 个门禁脚本
- 任务包目录契约
- 给单个 AI agent 端到端跑通

**对应产物**：原 `执行规范/` + `工作流主包/`

**问题**：
- 同样的事故反复发生，靠加规范条款防复发
- 改一条规则要动 3 处文档
- 给人/给机器的指令混写
- 自动化跑通可以，但"对外发布"不可行

---

## 阶段 2：半自动化（19:00 - 22:00 第一性原理对齐）

**定位转变**：从"AI 自动跑通"→ "AI 出草稿 + 人审 + 重做/编辑 + 下一步"

**关键判断**：
- 教学法不可自动化（"动作链、探究链路、证据表达"这些是教研员判断）
- 完整端到端自动化的产物总要被人改一遍，不如直接让人在中间介入
- 用户要"绝对主导权"，不要"AI 一键生成黑盒"

**对应产物**：v1_产品决策记录.md v1（5 设计点起步配置）

**特征**：
- 五状态机（not_started / drafted / needs_review / approved / blocked）
- 函数式 pipeline 契约（f(上游 approved, 规范) → 产物）
- 重做+编辑双通道
- 连锁失效降级

**仍未解决的问题**：
- 效率是核心卖点吗？用户为什么要来用？

---

## 阶段 3：震撼力 + 飞轮（22:30 - 00:00 关键拐点）

**定位转变**：核心卖点不是效率，是"眼前一亮的课件 + 越用越懂我"

**触发瞬间**：用户说

> "用户的目标是有一个好的教案，因为上课都会上，他们需要的是让人眼前一亮的教案和导入视频。这个也是我们需要对外展示的，不然他们不会来用我们的。"

> "闭环就是用户使用了这个东西，拿到了他想要的课件，我们系统会记住用户的习惯和偏好。并为生成个性化的记忆和偏爱风格，以后他就会越用越顺手。"

**关键判断**：
- 用户不是因为"AI 省时间"来，是因为"AI 能做出他自己做不出的东西"
- 飞轮不是锦上添花，是核心商业资产
- 冷启动质量必须打满（教研员第一眼就觉得震撼）
- 用户粘性来自"越用越懂我"，不是来自"流程顺"

**对应产物**：v1_产品决策记录.md v2（775 行重写）

**新增机制**：
- 第 0 章第一性原理（产品定位重构）
- 第 9 章逐页审查智能体（PPT 质量门禁）
- 第 10 章飞轮独立成章
- 第 12 章视频专用机制（首帧测试 + 6 段并发 + 拼接前审查）
- 反馈机制（课件到手 + 第二次使用弹窗）
- 偏好画像可视化（让用户看到"系统理解的我"）

---

## 阶段 4：从规范集到可执行基线（00:00 - 01:30）

**定位再转变**：产品不只是"规范文档"，要做成"机器能直接消费的执行基线"

**触发瞬间**：用户问

> "这个能不能直接串联作为整个工作流的参考基线。是否是血？可以注入流通的？"

**关键判断**：
- 5 份 Markdown 文档是给人读的，不能让代码直接吃
- 必须有 JSON Schema / workflow.yaml / 结构化规则 / 真实 prompt 这种"机器层"
- 三层契约：人读层 → 机器层 → 代码层

**对应产物**：`半自动化工作流/` 75 个文件（19 schema + 37 rules + 12 prompts + 配套）

**特征**：
- workflow.yaml 是状态机真源（改 yaml 不改代码）
- JSON Schema 驱动前端表单 + LLM 输出校验 + 数据库列定义
- 规则与执行解耦（builtin / script / agent 三种执行器）
- prompt 跨 provider 适配

---

## 三个定位的本质差异

| 维度 | 阶段 1：规范化 | 阶段 2：半自动化 | 阶段 3：震撼力+飞轮 | 阶段 4：可执行基线 |
|---|---|---|---|---|
| **用户为什么来** | 没想过（内部用） | AI 帮我提效 | AI 做出眼前一亮的 | 同 3 |
| **AI 的角色** | 端到端跑通 | 出草稿 | 出草稿 + 学风格 | 同 3 |
| **人的角色** | 写 prompt | 审 + 编辑 + 重做 | 主导 + 反馈 + 训练 AI | 同 3 |
| **核心资产** | 规范文档 | 工作流契约 | 飞轮数据 | 飞轮数据 + 可执行基线 |
| **核心交付** | PPT + 视频 | 同上 | 同上 + 偏好画像 | 同上 |
| **产品形态** | CLI / 脚本 | 网页 | 网页 + 飞轮可视 | 网页 + DAG 引擎 + 飞轮 |

---

## 下一个可能的定位演进（未发生）

### 阶段 5？协作化
- 教研团队多人分工
- 触发条件：内部有多个老师同时用、互相想借鉴

### 阶段 6？平台化
- 不只是单产品，是教研团队的 AI 中枢
- 触发条件：跨学科（数学 → 语文 / 英语）扩展

### 阶段 7？社区化
- 用户间分享角色字典、视觉契约、好课例
- 触发条件：用户规模过千

这些都是"等数据说话"的判断，不预设。

---

## 一句话总结

我们不是在"做一个 AI PPT 工具"。
我们在做"一个让教研员越用越像自己、且能做出他自己手做不出的课件的产品"。
震撼力 + 主导权 + 飞轮，三者缺一不可。
