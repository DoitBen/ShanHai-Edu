# 开发调度台账

> 由首席系统架构师维护。记录当前所有已下发、进行中、待接手的任务单。
> 各角色接到任务后，先读取本文件确认任务范围，完成后在对应记录中更新状态和产出摘要。

## 使用规则

- 首席系统架构师下发任务时，在"当前任务板"新增一条记录，状态标记为 `待接手`。
- 角色接手任务后，将状态改为 `进行中`，并在"接手角色"列填写角色名。
- 任务完成后，将状态改为 `已完成`，在"产出摘要"列简述结果，并在 `handoffs\latest.md` 更新交接。
- 任务被拒绝或阻塞时，标记 `阻塞`，在"备注"列说明原因并 @ 首席系统架构师处理。
- 历史任务按月归档到"历史任务"区，当前任务板只保留活跃记录。
- 任务验收默认遵循 V0.4 总控闭环：架构师下发任务 → 专业角色交付 → 测试工程师验收 → 架构师对照原任务、交付物、测试报告和关键代码/配置 diff 复核 → 通过或再派发。
- 前端、后端、运维可并行的前提是接口契约、数据结构和验收口径已经明确；不明确时先下发契约/PRD/运行边界任务。

## 调度说明

### 任务优先级定义

| 优先级 | 含义 |
|---|---|
| 紧急 | 阻塞主流程或有破坏性风险，需当轮处理 |
| 高 | 影响当前阶段目标，优先于其他任务 |
| 中 | 本阶段内完成，不阻塞当前主线 |
| 低 | 有价值但可延后，不影响阶段目标 |

### 任务状态定义

| 状态 | 含义 |
|---|---|
| 待接手 | 已下发，尚未有角色认领 |
| 进行中 | 已有角色接手，正在执行 |
| 已完成 | 角色已完成交付，产出已沉淀 |
| 阻塞 | 执行中遇到阻塞，需架构师或用户介入 |
| 已取消 | 任务被撤销或被其他任务替代 |

### 架构师下发任务的标准格式

```markdown
| T00X | YYYY-MM-DD | 目标角色 | 任务描述（明确范围、不做什么、产出格式） | 优先级 | 待接手 | — | — | 备注 |
```
