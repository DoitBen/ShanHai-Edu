## 总体结论

当前项目不建议进入可交付或部署状态。

核心阻断项：

- 后端 API 无真实鉴权与授权边界。
- 前端角色权限可由任意已登录用户自提权。
- 前端 TypeScript 错误被 Next 构建配置掩盖。
- Windows / Bun 环境下 `dev` 与 `build` 脚本不可重复执行。

已确认的正向结果：

- 后端 MVP 单测通过。
- 前端 lint 通过。
- 浏览器抽样可登录工作台。
- 配置页可读取后端 `/video/capabilities` 能力矩阵。

## 致命缺陷

### 1. 后端项目与节点接口无鉴权

- 分类：权限 / 后端 / 接口
- 位置：`apps\api\app\main.py:66`
- 复现步骤：
  1. 不携带任何认证信息。
  2. 直接请求 `POST /projects`。
  3. 接口返回 200，并成功创建项目。
- 风险影响：
  - 任意本机或同网段调用方可创建项目、上传文件、推进节点、读取资产与任务。
  - 后续接入真实 provider 后，可能造成成本消耗、数据泄露和任务污染。
- 标准修复方案：
  - 增加统一认证依赖。
  - 所有项目资源按用户、角色、项目归属做授权校验。
  - 未认证返回 401，越权返回 403。
  - 为项目、节点、任务、资产接口补充鉴权测试。

### 2. 前端任意已登录用户可切换为管理员

- 分类：权限 / 前端
- 位置：`apps\web\src\components\layout\TopBar.tsx:141`
- 复现步骤：
  1. 使用教师账号登录。
  2. 打开顶部用户菜单。
  3. 点击“切换为管理员”。
- 风险影响：
  - 教师角色可自提权访问配置、日志、脚本等管理功能。
  - 前端角色隔离失效。
- 标准修复方案：
  - 移除生产路径中的角色切换入口。
  - 用户角色从服务端 session 或 JWT 获取。
  - 前端菜单只展示服务端授权后的功能。
  - 管理功能接口必须由后端再次鉴权，不能只依赖 UI 隐藏。

## 严重缺陷

### 3. Next 构建跳过类型检查，掩盖 TypeScript 错误

- 分类：环境配置 / 前端
- 位置：`apps\web\next.config.ts:5`
- 复现步骤：
  1. 执行 `bunx tsc --noEmit --pretty false`。
  2. 观察 `mock-data.ts`、`store.ts` 和 websocket 示例依赖报错。
  3. 执行 `bun run build`，Next 输出显示跳过类型校验。
- 风险影响：
  - 类型不一致可能进入构建产物。
  - 状态流转、项目状态字段和 mock 数据结构存在运行时风险。
- 标准修复方案：
  - 修复所有 TypeScript 错误。
  - 关闭 `ignoreBuildErrors`。
  - 示例代码移出 `tsconfig` include 范围，或补齐示例依赖。

### 4. dev / build 脚本不兼容当前 Windows / Bun 环境

- 分类：环境配置 / 部署
- 位置：`apps\web\package.json`
- 复现步骤：
  1. 执行 `bun run dev`。
  2. 因 `tee` 命令不存在失败。
  3. 执行 `bun run build`。
  4. Next 编译成功后，因 `cp -r` 失败导致整体退出 1。
- 风险影响：
  - 本地开发启动不可重复。
  - 构建命令不可作为发布门禁。
  - CI / 部署脚本在 Windows 环境不稳定。
- 标准修复方案：
  - 用跨平台 Node 脚本或 Bun 兼容脚本替代 shell 管道和 `cp -r`。
  - 构建产物复制前做存在性检查。
  - 将 `dev` 日志写入改为跨平台方案。

### 5. 教材上传接口无类型、大小、内容校验

- 分类：接口 / 安全 / 文件操作
- 位置：`apps\api\app\store.py:283`
- 复现步骤：
  1. 上传 `textbook.exe`。
  2. MIME 设置为 `application/octet-stream`。
  3. 接口返回 200，并落盘到 `uploads/textbook.exe`。
- 风险影响：
  - 任意文件可写入项目目录。
  - 后续如果提供下载或预览能力，风险会扩大。
- 标准修复方案：
  - 限制扩展名、MIME 类型和文件大小。
  - 校验 magic bytes。
  - 落盘前生成服务端安全文件名。
  - 拒绝可执行文件和未知二进制。

### 6. 节点生成接口缺少幂等控制

- 分类：接口 / 数据逻辑
- 位置：`apps\api\app\services.py:43`
- 复现步骤：
  1. 创建项目并上传合法 `.txt` 教材。
  2. 连续两次请求 `POST /projects/{project_id}/nodes/textbook_parse/generate`。
  3. 两次都返回 200，并写入两个版本。
- 风险影响：
  - 重复点击或并发请求会造成版本污染。
  - 接入真实模型后会重复消耗成本。
  - 当前版本、任务、事件记录可能难以追溯。
- 标准修复方案：
  - 增加 request id / idempotency key。
  - 节点生成期间加 running 锁。
  - 同输入、同节点重复请求返回既有任务或 409。

## 一般缺陷

### 7. 前后端缺少常见安全响应头

- 分类：基础安全 / 环境配置
- 复现步骤：
  1. 请求后端 `/health`。
  2. 请求前端首页。
  3. 检查响应头。
- 风险影响：
  - 缺少 CSP、HSTS、X-Frame-Options、Referrer-Policy 等基础安全防护。
  - 前端暴露 `X-Powered-By: Next.js`。
- 标准修复方案：
  - 在 Next / FastAPI / Caddy 统一补充安全头。
  - 生产环境关闭 `X-Powered-By`。

### 8. 依赖审计存在高危漏洞

- 分类：基础安全 / 供应链
- 复现步骤：
  1. 在 `apps\web` 执行 `bun audit`。
  2. 审计工具报告 54 个漏洞，其中 24 个 high。
- 风险影响：
  - Next、next-intl、lodash、prisma 等依赖链存在已知漏洞。
  - 是否可被本项目路径触发还需逐项确认。
- 标准修复方案：
  - 优先升级 Next 到修复版本。
  - 处理 direct dependency。
  - 再处理 transitive dependency。
  - 升级后重新执行 lint、typecheck、build 和浏览器主流程验证。

### 9. 登录页和页脚展示演示账号密码

- 分类：前端 / 安全
- 位置：`apps\web\src\components\screens\LoginScreen.tsx:24`
- 复现步骤：
  1. 打开登录页。
  2. 页面默认预填账号密码。
  3. 页脚显示 `admin / shanhai2026`。
- 风险影响：
  - 若误部署到可访问环境，等同公开演示凭据。
- 标准修复方案：
  - 演示账号仅在开发环境展示。
  - 生产环境必须走真实认证。
  - 页脚移除任何凭据提示。

## 优化建议

### 10. 前后端主业务尚未完成真实集成

- 分类：功能流程 / 架构
- 现状：
  - 前端主业务仍以 `MOCK_PROJECTS` 和 zustand 本地状态为主。
  - 目前只有配置页读取了后端 `/video/capabilities`。
- 风险影响：
  - UI 主流程看似完整，但项目创建、上传、节点生成并未真实流转到后端。
  - 后续联调会暴露更多状态同步问题。
- 建议方案：
  - 明确“演示版”和“MVP API 联调版”边界。
  - 优先打通项目创建、教材上传、节点生成、节点审批、任务查询五个关键 API。

### 11. 本地多项目端口占用容易误判

- 分类：环境配置 / 开发体验
- 现状：
  - `3000` 当前为其他项目页面。
  - `3001` 为本项目 Next 服务。
  - `8000` 为本项目 FastAPI 服务。
  - 启动新 Next 服务时遇到 `.next\dev\lock` 占用。
- 建议方案：
  - 增加端口探测说明。
  - 开发脚本启动前输出当前端口占用进程。
  - 文档中说明如何安全停止旧服务，避免误杀用户进程。
